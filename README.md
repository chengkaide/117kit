# 117kit · 117 实验室管理及小工具系统

LA-ICP-MS 实验室（117 实验室）的网页版管理系统。部署在校园网内一台电脑上，
校园网内的手机 / 电脑浏览器均可访问，支持"添加到主屏幕"当 App 用（PWA）。

## 功能（当前版本）

| 模块 | 说明 |
|------|------|
| 用户系统 | 注册需管理员审批；首个注册用户自动成为管理员；角色：成员 / 管理员 |
| 打卡 | 每日签到签退，历史记录可查 |
| 实验预约 | 未来两周日历；周一至周五为工作日，周六日也开放预约；同一仪器时段冲突自动拦截 |
| 实验数据与结果 | 上传实验数据文件；提交最终结果；**实验数据与结果仅本人和管理员可见**（服务端强制） |
| 气体状态日报 | 每天登记氮气、氩气、高纯氦、高纯氮的压力与余量（含周六周日） |
| 记录本 | 手机拍照上传实验室记录本，按日期归档 |
| 配件位置台账 | 名称 / 类别 / 房间 / 柜号 / 具体位置，支持搜索 |
| 运行记录 | 温度/湿度/数据点数/标样点/样品点/信号参数与强度/意外事件，可导出 CSV |
| 值班日志 | 值班情况与交接，可导出 CSV |
| Qtegra 数据 | 自动监视导出目录，原始信号数据（cps×sweep）自动解析入库；也可手动上传 |

## Qtegra 对接

在 Qtegra 里配置分析完成后自动导出 CSV 到目录 `server/qtegra-inbox`（环境变量
`QTEGRA_WATCH_DIR` 可改）。服务运行期间，新文件写入完成后约 1-2 秒自动解析入库：

- 解析规则：第 1 行取样品名和测定时间；以"第一个字段以 Time 开头"定位表头；
  字段数一致且第 2 列为数字的行视为数据（不写死行号，兼容 Qtegra 不同版本）
- 导入成功 → 文件移入 `qtegra-inbox/imported/`；失败（含重复文件）→ 移入 `failed/`
- 数据按 sha256 去重；原始信号（每个 sweep 的全部同位素 cps）以 JSON 存库，供后续归算使用

## 商业化路线（预留）

当前定位为**单实验室内网自用版**。走向商业软件需要（按优先级）：
1. 安装产品化：pkg/electron 打包成单 exe + Windows 服务注册（开机自启）+ 一键安装包
2. License 授权：授权码绑定机器指纹（主板 UUID + MAC），到期提醒，离线激活
3. Qtegra 数据自动归算：把 TERMITE/ADEPT 的归算算链接到导入流程（原始数据已就位）
4. 多实验室支持（若走 SaaS）：当前数据库按"本人/管理员"隔离，加 lab_id 字段即可升级多租户
5. 注意：与 Qtegra 的集成走"文件夹导出"路线，不触碰 Thermo 软件本体，无许可风险

## 启动

```bat
cd server
node src/index.js
```

或双击根目录 `启动117kit.bat`。浏览器打开 `http://localhost:3117`。
局域网其他设备访问 `http://<这台电脑的IP>:3117`（首次运行需在 Windows 防火墙放行 3117 端口）。

首次使用：打开网页 → 注册 → **第一个注册的账号自动成为管理员** → 登录后在"管理"页审批其他成员。

## 数据与备份

- 数据库：`server/data/117kit.db`（SQLite 单文件，WAL 模式）
- 上传文件：`server/uploads/`（按类型分目录，随机文件名存储，原始文件名在数据库中）
- **备份 = 复制这两个目录**。建议每天下班前拷到移动硬盘。

## 安全设计

- 密码 scrypt 哈希（Node 内置），不可逆
- 会话：服务端 Session + HttpOnly Cookie（可随时吊销；改密/停用立即全端下线）
- 登录限流：同一用户名+IP 连续失败 5 次，锁定 15 分钟
- 上传：扩展名白名单 + 大小限制（默认 200MB）；文件不经公开静态目录，全部走鉴权接口下发
- 权限：实验数据/结果在**服务端查询层**按"本人或管理员"过滤，不是前端隐藏
- 安全响应头：nosniff / DENY iframe / CSP / HTTPS 时自动 HSTS
- 结构化 JSON 日志（`server/.srv.log` 运行时可重定向），每请求带 request id

环境变量（可选）：`PORT`、`SESSION_SECRET`（多实例/重启保会话时设置）、
`MAX_UPLOAD_MB`、`LOGIN_MAX_ATTEMPTS`、`SESSION_DAYS`、`DB_FILE`、`UPLOAD_DIR`、`CORS_ORIGINS`。

## 技术栈与演进

Node.js 22（内置 `node:sqlite`，零原生依赖）+ Express + busboy；前端为零构建单页应用
（`client/dist/`，纯 HTML/CSS/JS + Service Worker）。刻意保持简单：**每个模块以后都可以
独立加厚**（如预约改日历拖拽、实验接 LA-ICP-MS 数据自动解析、接入微信小程序等），
后端 API 已按模块拆分，前端可逐步迁移到 React 而不影响接口。
